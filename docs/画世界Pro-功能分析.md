# 画世界Pro 功能分析：哪些值得搬进画界

> 目的：把画世界Pro的功能面摊开，判断这套"Dsh 画界"插件该学什么、该放弃什么。
> 结论先行：值得学的是**结构化编辑**（图层、选区、历史），不是**像素特效**（滤镜、液化、混合模式）。

## 一、画世界Pro 的功能面

按官方商店页和第三方介绍，它的能力大致分六组：

| 组 | 内容 |
|---|---|
| 笔刷系统 | 100+ 内置笔刷（勾线/上色/水彩/水墨/油画）；100+ 可调参数；导入导出 BRU 画笔、导入 Photoshop ABR |
| 图层与合成 | 图层组、整组混合模式、剪切蒙版、28 种混合模式、纸纹背景、自动匹配图层数 |
| 工具与辅助 | 压力感应、独立压感曲线、倾斜压感、抖动修正、快速图形（矩形/圆/直线/柳叶笔）、取色设置、油漆桶/渐变、对称（水平/垂直/镜像/曼陀罗）、透视辅助线 |
| 选区与变形 | 魔棒/套索/画笔/矩形选区、自由/扭曲/标准变形、液化 |
| 滤镜 | 曲线、渐变映射、查找边缘、高斯模糊、色散、浮雕、油画 |
| 动画与输出 | 洋葱皮、多轨、GIF/MP4 导出、PSD 导出、无损 PNG/JPG、绘制过程记录与回放 |

性能侧还强调 GPU 加速、无限撤销重做、大画布多图层。

## 二、本插件现在有什么

从代码（`index.js` / `client.js`）读出来的真实能力：

- 文档模型：`doc.json`，单层 `strokes[]`，每笔是 `[x, y, pressure]` 点序列 + `color/size/opacity/mode`
- 渲染：前端 canvas 按压感插值笔宽（`0.25 + 0.75 × pressure`），端点圆头
- 模型工具 `paint_canvas`：`doc`（摘要）/ `draw`（落一笔）/ `view`（取渲染 PNG）/ `undo` / `clear`
- 人的界面：颜色、笔宽滑杆、撤销、清空、笔迹计数
- 设置页：画布尺寸、背景色、缓存目录、保存路径、另存 PNG
- 版本/存储：`settings.json` 存路径，`doc.json` 存笔迹，`preview.png` 存最近渲染

对照之下缺的是：图层、选区、形状约束、重做、抖动修正、参考图、过程回放、透明导出、PSD。

## 三、逐项判断

判断用两个轴：**模型能不能用好**（能不能用几行 JSON 表达、模型是否能预测结果），**实现成本**（改数据结构还是只改渲染）。

| 画世界Pro 能力 | 本插件现状 | 判断 |
|---|---|---|
| 压力感应 | 有（数据里就是压感值） | 保留，已经是核心优势 |
| 压感曲线 / 倾斜压感 | 无 | 不必做：模型给的是数值压感，曲线是给手写笔调手感的 |
| 100+ 笔刷、ABR/BRU 导入 | 已做 32 支，分八类（常规/勾线/铅笔素描/水彩/水墨/油画/喷枪/特效），13 种落笔方式 | 不做 ABR/BRU 导入（贴图笔刷要纹理资源）；笔刷走「参数化的手感」而不是贴图，加一支只加一行 |
| 抖动修正 | 无 | 人有用、模型无意义；低成本可做（前端平滑），优先级低 |
| 快速图形（矩形/圆/直线） | 无按钮，但模型可直接算点画出来 | 人端值得加一个形状工具，模型端不需要 |
| 图层组 / 28 种混合模式 | 无，单层 | **图层值得做**（哪怕 2~4 层 + 显隐 + 不透明度）；混合模式先只做 normal/multiply |
| 剪切蒙版 | 无 | 不做，语义复杂且模型难用 |
| 选区（魔棒/套索/矩形） | 无 | 矩形选区可以做（裁剪提交的笔迹）；魔棒/套索依赖像素分析，先不做 |
| 变形 / 液化 | 无 | 不做，属于像素管线 |
| 滤镜（曲线/渐变映射/模糊） | 无 | 不做：与"笔迹是数据"的模型冲突，做进去就得引入栅格层 |
| 洋葱皮 / 动画 / GIF、MP4 | 无 | 不做，场景不匹配（这插件是聊天里画示意图，不是做动画） |
| 无限撤销重做 | 只有 undo（最近 N 笔） | **redo 必做**，成本极低；撤销栈天然就是数据 |
| 绘制过程回放 | 无 | 值得做：笔迹有序，回放就是按序重绘，还能给模型做"逐步检查" |
| 导出 PSD / 透明 PNG | 只导出带背景 PNG | 透明 PNG 成本低可做；PSD 要写图层结构，等图层落地后再考虑 |
| 参考图导入 | 无 | 值得做：模型多模态，用户也可给参考；作为只读图层存文件引用 |

## 四、三条结论

1. **先补结构，不补特效。** 图层、redo、选区（矩形）、过程回放这四个都是"数据层"改动，改完模型和人都受益；滤镜/液化/变形是"像素层"改动，一旦引入，`doc.json` 就不再是可推断的数据结构，模型也没法可靠控制。
2. **图层要现在做，不要等。** `strokes[]` 升级成 `layers[{ id, name, visible, opacity, blend, strokes }]` 会同时牵动前端渲染、`doc` 摘要、导出、模型工具签名（`draw` 加 `layer` 参数）。拖得越久，改动面越大。
3. **画世界Pro 真正值得借鉴的是它对"编辑动作"的建模**：选区是可保存的几何、图层是独立可寻址单元、历史是有序操作。这些都能用 JSON 表达；而滤镜、液化、混合模式是渲染期效果，不该进文档。

## 五、如果要做图层，数据结构怎么摆

```jsonc
{
  "version": 2,
  "width": 1024, "height": 1024,
  "background": "#ffffff",
  "activeLayer": "l1",
  "layers": [
    { "id": "l0", "name": "草稿", "visible": true, "opacity": 0.4, "blend": "normal", "strokes": [] },
    { "id": "l1", "name": "线稿", "visible": true, "opacity": 1, "blend": "normal", "strokes": [] }
  ]
}
```

迁移：读到 `version: 1` 的旧文件，把顶层 `strokes` 搬进一层 `layers[0]`，写回 `version: 2`。
模型侧工具加两个参数即可：`draw` 的 `layer`、`doc` 返回每层的笔迹数与显隐。

## 六、不推荐现在动的

- 动画/洋葱皮：没有时间轴需求，做了也没人用。
- 28 种混合模式：先 normal 一种，最多加 multiply，够画阴影。
- 滤镜：真要做，就得承认"文档里要存栅格结果"，那是另一个产品。
- PSD 导出：等图层稳定后再评估，格式成本远高于收益。
